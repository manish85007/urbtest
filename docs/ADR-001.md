# ADR-001: Urb TecTrack production stack

**Status:** Accepted  
**Date:** 2026-08-15

## Context

Urb TecTrack has a complete HTML prototype encoding business rules from operational feedback. The production build plan requires porting — not rewriting — those rules into a hosted, multi-tenant, audit-ready platform with Indian data residency.

## Decision

| Area | Decision | Rationale |
|------|----------|-----------|
| API style | REST | Prototype service objects (`db.subs`, `db.inv`, `auth`, …) map 1:1 to resources |
| Runtime | Node.js 20 + TypeScript | Same language as prototype; shared domain package |
| HTTP framework | Fastify | Lightweight, typed, good cookie/session support |
| ORM | Prisma | Versioned migrations from day one; team familiarity |
| Database | Managed Postgres (dev: Docker) | Build plan recommendation; RLS in Phase 2 |
| Frontend | React + Vite | Phase 6 migrates prototype screens incrementally |
| Money | `BIGINT` paise | Avoid floating-point invoice drift |
| Weights | `DECIMAL(12,3)` kg | Weighbridge + recovery reconciliation |
| Stage | Derived in shared lib + SQL views | Prototype v6.3 fix — counters drift |
| MRN sequence | `mrn_counters` upsert in transaction | Concurrency-safe per build plan Appendix E |
| Auth | bcrypt + HttpOnly session cookie | Replace prototype SHA-256 |
| Files (later) | S3 pre-signed URLs | Phase 4 |
| Email (later) | Async queue + SES/SendGrid | Phase 5 |

## Consequences

- Business logic lives in `@urb-tectrack/shared` and API services, tested against prototype assertions.
- Frontend initially a thin shell; full UI ports from prototype CSS/JS in Phase 6.
- India region hosting (AWS ap-south-1) required before production — not configured in this scaffold.
